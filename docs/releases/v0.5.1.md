# Agentao 0.5.1

A **stabilisation release** after 0.5.0's removals and its opt-in
`anthropic-messages` wire. Nothing is removed and nothing needs migrating. Most
of it is things agentao *said* that were not true — a token total that left
sub-agents out, a `/temperature` that reported sending what it never sends, a
context window shown at a size no budget was using — and one request that was
sent for a task already cancelled.

## Usage you can account for

**A sub-agent's tokens are counted.** A sub-agent is a separate `Agentao` with
its own LLM client, so its requests were in nobody's total: `/status` and
`agentao run`'s `usage` reported a delegating run as costing only the parent's
own calls. Each sub-agent's totals are now added to the parent's when it
finishes — including a run that raised or was cancelled, whose requests were
paid for either way. A foreground sub-agent lands inside the parent's turn; a
background one when it ends, from its own thread, which is why the totals now
have one thread-safe writer, `LLMClient.add_usage()`.

**The totals say how much of the input was cached.** `prompt_tokens` is the
*whole* prompt on every wire — what compaction needs, and what makes it useless
for cost, since providers bill cache reads and writes at other rates. New, and
all additive:

| Surface | New |
|---|---|
| `LLMClient` | `total_cache_read_tokens`, `total_cache_creation_tokens`, `reset_usage()` |
| `agentao run` → `usage` | `cache_read_tokens`, `cache_creation_tokens` |
| `LLM_CALL_COMPLETED` (and replay) | the same two keys |
| `/status` | `Session: 5,100 prompt (4,000 cached, 200 cache-write) / 40 completion` |

Both are parts **of** the prompt count, not additions to it. They are read from
`cache_read_input_tokens` / `cache_creation_input_tokens` on the Anthropic wire
and from `prompt_tokens_details.cached_tokens` on Chat Completions, which has no
cache-write count. **Agentao applies no prices** — that table changes with
time, provider and gateway, and is the host's.

These are usage, not an invoice: a request that failed mid-stream may go
uncounted, and a background sub-agent can finish after `agentao run` has
written its envelope.

## A cancelled task no longer sends its request

Both wire adapters first read the cancellation token *inside* their event loop —
after the request had gone out and the first event had come back. A turn
cancelled in that gap still sent the generation request and paid for the whole
prompt. On the `anthropic-messages` wire the gap was seconds wide, because the
Models API lookup runs in it. `chat_stream` now checks on both sides of that
lookup: a turn already cancelled does not start it, and one cancelled during it
sends nothing. The turn reports `status="cancelled"` as a mid-stream cancel
already did; there is no new exception. The lookup itself is still not
interruptible — what is promised is that a cancelled task is not *continued*.

## The CLI says what is so

- **`/context` names a window the Models API narrowed.** The "Effective" line
  appeared only after an overflow had been *observed*, so a window narrowed by
  the model's `max_input_tokens` — which needs no overflow — was invisible:
  the configured number on screen, a smaller one behind every budget. It now
  names both inputs.
- **`/context` says which quantity its total is** —
  `(last request, as the API counted it)`, exact but one step behind, or
  `(local estimate)`.
- **`/temperature` no longer says "sending 0.7" on `anthropic-messages`**, which
  never sends it. The value is still stored: a `/provider` switch back to Chat
  Completions uses it.

## Examples

- **`examples/anthropic-wire/`** is the first example to name `api_format`: the
  one-keyword change, what differs on that wire, and a usage report. Its smoke
  runs a scripted socket under the real `anthropic` SDK — no key needed.
- **Every example's `uv.lock` was stale** — none listed `anthropic`, a core
  dependency since 0.5.0, so an environment installed `--frozen` from one could
  not use the new wire. CI never noticed because a bare `uv sync` re-resolves
  quietly; it now runs `--locked`. If you change agentao's dependencies, run
  `uv lock` in each example directory.

## Measured, and how to measure it yourself

`scripts/measure_prompt_cache.py` is the kept form of the prompt-cache
comparison in `docs/design/llm-api-adapters.md`. It sends nothing without
`--yes`. On `api.anthropic.com` with `claude-sonnet-5`, the native wire's input
cost came to **−77%** against its own full price, with 22 tokens in the whole
session billed at the full rate — reproducing the −78% recorded earlier.

Read that number for what it is: **one scripted session on one endpoint.** On
Anthropic's OpenAI-compatible endpoint the response carries no cache fields at
all, so whether caching also happens there is visible only on the bill — the
measurement shows where the saving can be *measured*, not that it exists
nowhere else.

On a second vendor (an Anthropic-compatible and an OpenAI-compatible endpoint
fronting the same model) all four arms landed within three points of each other
— 88.9–91.5% of input read from cache — **with or without `cache_control`
marks, on either wire**. That endpoint caches prefixes on its own; what earned
the hits there is the byte-stable prefix 0.4.26 introduced, and
`LLM_PROMPT_CACHE` bought nothing measurable. It stays off by default. Two
vendors is not a survey: point the script at your own endpoint before treating
any of this as a saving.

## Upgrading

```bash
pip install -U agentao
```

No API was removed or changed. `LLMClient.add_usage()` and `reset_usage()` are
new; the two `usage` keys and the two event keys are additions, and consumers
that ignore unknown fields are unaffected.
