# Agentao 0.4.20

A **compaction-orchestration release**, with a correctness tail.

Five places in the codebase detected that the context window was filling up and
each one compacted it in its own way. They disagreed about the two things that
matter — whether a failure counts against the circuit breaker, and whether
"compacted" means the history actually changed — and none of them let the host
say no. This release replaces all five with one coordinator, one outcome per
attempt, and events that only fire when something happened.

The headline:

- **One `CompactionCoordinator`, one `CompactionOutcome` per attempt.** Every
  compaction now reports a `status` — `success`, `cancelled`, `failed`, or
  `skipped` — and the difference between the last two is load-bearing:
  `failed` was attempted and did not succeed, `skipped` means nothing was
  attempted at all.
- **`PreCompact` can say no.** It was notify-only. A command hook can now
  cancel a compaction, and an embedded host can pass a
  `compaction_controller=` that cancels or supplies its own summary.
- **The circuit breaker is recoverable.** Three consecutive failures used to
  disable automatic compaction for the rest of the session with no way back —
  including through manual `/compact`, the one action a user could take.
- **The context window is validated against the provider.** `max_tokens` stays
  the host's knob; a second, lower ceiling is now learned from the provider's
  own overflow errors, and every internal budget is denominated in it.
- **The summarizer is fed what the prompt actually asks for.** It demanded
  error messages verbatim while the input pipeline had already clipped every
  tool result to 200 characters. Ordinary windows go from about 15% retention
  to 46-76%.

And the correctness tail, which is unrelated to compaction but ships here:

- **Invisible Unicode tag characters were passed straight to the model.** A web
  page, an MCP result or a file could carry instructions that render as nothing
  in the terminal, nothing in a diff, and read perfectly to the model.
- **Stale thinking artifacts went back on the wire after a model switch**, to a
  model that never issued them.
- **A turn that ran out of tool-call iterations reported itself as an answer.**
  An embedded host reading `agent.last_turn` could not tell the harness's
  "Maximum tool call iterations reached." string from a real reply.
- **A broken `permissions.json` no longer loads as zero rules.** It fails
  closed instead.

## Breaking changes

Two, both in the permission loader, and both are the same decision: a security
policy file that cannot be understood must not be treated as an empty policy.

1. An unreadable, non-UTF-8, malformed, or structurally wrong
   `permissions.json` now **aborts session creation** instead of silently
   loading no rules. A file you cannot parse is not a file that permits
   nothing — it is a file whose contents you do not know.
2. Permission rules are validated, and an unknown `action` is now an error
   rather than being ignored. A one-word typo used to be a silent privilege
   escalation: the engine read exactly four keys off a rule and type-checked
   none of them, so an unrecognised key — usually the rule's *condition* — was
   dropped and the rule widened to the whole tool.

If your `permissions.json` is valid today, neither change is visible. If it is
not, you will find out at startup rather than at the first tool call.

## Why compaction, and why now

Compaction is the one subsystem that can permanently destroy state. Its output
replaces the conversation; there is no undo, and nothing downstream can tell a
faithful summary from a lossy one. That makes every defect in it a silent one,
which is exactly the class this release is about:

- A summary that reported a tool result had lost 40 characters when it had lost
  197,020 — because the truncation notice was written outside the limit that
  produced it, so the clip re-selected its own output and cut its own honest
  count out of the middle.
- A compaction that returned the history unchanged on every iteration, forever,
  because the split point insisted on a `user` message and a tail of twenty
  assistant/tool messages has none.
- A `CONTEXT_COMPRESSED` event reporting `pre == post` on every loop iteration
  with the breaker already open, and a `PreCompact` hook subprocess forked each
  time to announce a compaction that would not run.

None of these produced an error. Two of them made the summary *less* accurate
while reporting success, and a summary is what the model believes about
everything it can no longer see.

## The host contract

Compaction now has a public control plane, documented in the host API
reference:

- `Agentao.compact(*, reason="manual_cli") -> CompactionOutcome` — the public
  entry, which also runs as a half-open probe through an open breaker.
- `compaction_controller=`, a keyword-only constructor argument. It receives a
  `CompactionDecisionContext` — counts, budgets and file paths, **never message
  text** — and returns `allow`, `cancel`, or `provide_summary(text)`.
- A `PreCompact` command hook can print
  `{"hookSpecificOutput": {"compactionDecision": "cancel"}}`.

Everything that is not an explicit cancel means allow, **including a raise**.
That is deliberate and not defensive style: two of the five entry points are
the API-overflow recovery ladder, so an exception escaping the control plane
would turn "context too long" into "the turn crashes".

The `PreCompact` payload's `trigger` field is also honest now. It was
hardcoded to `auto` at all five sites, so a hook could not tell a manual
`/compact` from a threshold compaction from an overflow recovery — the exact
distinction the field exists to carry.

## Two token units, named apart

Worth knowing before you wire up the new events. `CONTEXT_COMPRESSED` carries
`pre_est_tokens` / `post_est_tokens`, which **include** the system prompt. The
new `COMPACTION_SETTLED` carries `pre_tokens_history` / `post_tokens_history`,
which exclude it. They are named differently because they are not
interchangeable, and wiring one into the other will silently misreport.

Likewise `max_tokens` and `effective_max_tokens`: the first is what the host
configured and reads back what the host wrote, the second is
`min(configured, observed)`. `get_usage_stats()['max_tokens']` and ACP's
`session/set_model` echo both keep returning the configured value.

## Upgrading

`pip install -U agentao`, then check `permissions.json` parses if you maintain
one. Replay files gain schema version 1.3 for the new `COMPACTION_SETTLED`
event; older files still load.
