# Agentao 0.5.7

This release has four themes:

- **Fewer commands run without asking.** Several ways around the
  `workspace-write` / `plan` command list are closed: commands that run
  other commands, git options that write files or run programs, writes
  into `.git` or `.agentao`, and path rules that `./secrets/k` slipped
  past.
- **`temperature` is not sent unless you set it.** The provider's own
  default applies. Before, every request carried `0.2`.
- **Fewer turns lost to provider errors.** Errors that arrive inside a
  stream or in a `200` body are now retried when they are transient, or
  raised with the provider's message when they are not. A Responses stream
  that never finished a function call is refused instead of run. Two more
  context-overflow wordings now lead to compaction.
- **Fewer conversations lost.** The interactive CLI saves the session after
  every turn. An embedded host's `arun()` cancel now waits for the turn to
  end, and a second turn on a busy agent is refused.

Most of the permission and turn changes came from a review of codex's recent
fixes against agentao. The `.git/config` case below was reproduced, not
inferred.

No public method was removed. Several changes can affect an existing setup.
Read the next section before upgrading.

## Check this before upgrading

**1. `temperature` is no longer sent by default.** `LLMClient` and
`Agentao(temperature=)` now default to `None`, and an unset value puts no
`temperature` in the request. The provider's own default applies, which for
many chat models is `1.0`. A value you set through `LLM_TEMPERATURE`,
`temperature=`, `/temperature <value>` or a sub-agent's `temperature:` is
sent as before, `0.0` included. To keep the old sampling:

```bash
LLM_TEMPERATURE=0.2
```

`/temperature` and `/status` show an unset value as
`provider default (not sent)`. The `anthropic-messages` wire never sent
`temperature`, and nothing changes there.

**2. `workspace-write` asks before more shell commands, and `plan` refuses
them.** These commands now ask in `workspace-write` and are denied in
`plan`:

- a command using shell quoting, backslashes, parentheses or
  `* ? [ ] { }`. This includes everyday forms such as `ls *.md` and
  `grep "a b" f`;
- `env` and `file`, which are off the list;
- git's `--output`, `--ext-diff` and `--textconv`, or an abbreviation of
  them;
- a name that merely starts with a listed one, such as `cat-tool` or
  `git statusx`.

Before, `env sh -c ...` ran anything, `git diff --output=<path>` wrote
anywhere, and quoting such as `--out""put` hid an option from the pattern. If
you want a form back, add a user rule in `~/.agentao/permissions.json`. For
example, this allows `ls` with plain arguments and globs:

```json
{
  "rules": [
    {"tool": "run_shell_command", "args": {"command": "^ls( [\\w./*-]+)*$"}, "action": "allow"}
  ]
}
```

With that rule, `ls *.md` and `ls docs/*.md` are allowed. `ls $(rm x)` still
asks, and `ls; rm -rf x` is still denied by the command floor.

**3. Writes into `.git` or `.agentao` ask in `workspace-write`.** This covers
`write_file` and `replace` into a `.git` or `.agentao` directory, or onto a
`.git` file, at any depth. A `core.fsmonitor` written to `.git/config` ran on
the next auto-allowed `git status`, and `.agentao/` holds MCP servers, hooks
and plugins. A user `allow` rule still overrides this. Drivers already present
in your git configuration can still run from `git status` / `git diff`; this
change stops the model from adding one.

**4. `deny` and `ask` path rules match more spellings.** A rule on
`file_path` for `read_file`, `write_file` or `replace` is now matched against
the raw path, its resolved absolute path and its resolved project-relative
path. Before, `^secrets/` denied `secrets/k` and allowed `./secrets/k`,
`sub/../secrets/k` and the absolute path. `allow` rules are unchanged, so no
existing rule grants more than it did.

**5. At most 6 background sub-agents run at once.** A launch past the limit
is refused, not queued. The model is told to wait for one, cancel one, or run
the task in the foreground. `/agent bg` prints the refusal. Hosts can set the
limit (see *For embedded hosts*).

**6. The interactive CLI saves after every turn.** A closed terminal, a killed
process or a crash no longer loses the conversation. Each save replaces the
previous file for that session, so a session still takes one file. Two
consequences:

- `/sessions resume` used to discard the unsaved conversation it left. That
  conversation is now kept, up to its last turn.
- Resuming a session and exiting used to add a second file for it. The
  resumed session's saves now replace the file it was loaded from.

The per-turn save is not a session end: no `SessionEnd` hook fires and
nothing is printed.

## For embedded hosts

- **A second turn on a busy agent raises `TurnInProgressError`**
  (`agentao.runtime.turn`, a `RuntimeError`) before touching any state, for
  `chat()` and `arun()` alike. Two turns on one agent never worked, since they
  shared history and every per-turn counter, but nothing refused the second.
- **A cancelled `arun()` waits for its turn to end.** It cancels the token,
  then waits up to 5 s for the worker to finish the turn (orphaned tool
  results backfilled, `TURN_END` emitted) before re-raising
  `CancelledError`. Past 5 s it logs a warning and re-raises anyway. Before,
  a host that started the next `arun` right after the cancel ran it against
  history the first turn was still writing.
- **`save_session(..., supersedes=)`** and
  **`persist_agent_session(..., supersedes=)`** name an earlier file of the
  same session to remove once the new one is in place. That is how the CLI
  keeps one file per session. `save_session` now writes under a temporary
  name and renames it into place.
- **The background limit is configurable.** It is
  `BackgroundTaskStore(..., max_concurrent=)`: default `6`, `None` for no
  limit. The refusal is `agentao.agents.BackgroundCapacityError`:

  ```python
  from agentao.agents import BackgroundCapacityError
  from agentao.agents.bg_store import BackgroundTaskStore

  store = BackgroundTaskStore(max_concurrent=2)
  store.register("a1", "worker", "task one")
  store.register("a2", "worker", "task two")
  try:
      store.register("a3", "worker", "task three")
  except BackgroundCapacityError as exc:
      print("refused:", exc)
  ```

  Only this store's own pending and running tasks count, not another
  process's records in the same file.
- **`LLM_CALL_STARTED`'s `temperature` is `None`** when no value is set.

## Provider errors

- **Chat Completions retries a transient error inside a stream.** A gateway
  that has already sent `200 OK` reports an upstream failure as an
  `{"error": ...}` chunk. `server_error`, `rate_limit_exceeded` and a
  retryable numeric `code` (OpenRouter's documented shape) are now retried, as
  they already were on the other two wires. This applies only while nothing
  has reached the host.
- **A `200` body without `choices` raises the provider's error** instead of
  a `TypeError` that named neither the provider nor its message.
- **A Responses stream that never finished a function call is refused**
  (`ResponsesProtocolError`, not retried), and none of its calls are run.
- **Two more context-overflow wordings** (Z.AI GLM, and
  `Prompt has N tokens, but the configured context size is N tokens`) now go
  through compaction and retry.
- **A `Retry-After` date that has already passed means "retry now"**, not
  the ~9.5 s local backoff.
- **A tool call that sends `null` for an optional parameter** gets the
  tool's default. `read_file(offset=None)` used to fail with a `TypeError`.

## Other fixes

- **MCP:** with `mcp` 1.x, a Streamable HTTP server that fails the handshake
  now reports its error instead of ending silently disconnected. A redirect
  the SDK refuses no longer comes with a "try SSE" hint that could not help.
- **Oversized tool output** is saved under the session's
  `working_directory`, not the process's current directory, so `read_file`
  can find it in ACP and embedded sessions. Saved outputs older than 7 days
  are now pruned.
- **`agentao doctor` and `agentao config validate`** mask credentials in the
  provider's base URL.
- **Permission rules and hook matchers:** a rule pattern that overflows or
  nests too deeply to compile now falls back to literal matching instead of
  raising on every turn. A hook matcher that is not a valid regular
  expression is reported when the hooks file loads.

## Upgrading

```bash
pip install -U agentao
```

Check the numbered items at the top if you:

- rely on agentao sending `temperature: 0.2`;
- run in `workspace-write` or `plan` and expect globbed or quoted shell
  commands to run without asking;
- let the model edit files under `.git` or `.agentao`;
- embed `Agentao` and might start a turn while one is running, or cancel
  `arun()` and immediately start another.
