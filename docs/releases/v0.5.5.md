# Agentao 0.5.5

This is a fix release. It has three themes:

- **Bounded memory for large outputs.** A shell command or a `web_fetch`
  that returns hundreds of megabytes no longer takes the process with it.
  The model now sees both the start and the end of a long shell output.
- **Interrupts and resumes keep what they should.** A Ctrl+C mid-answer
  keeps the text already shown, a cancelled turn no longer counts against
  compaction, and a resumed conversation no longer reads its own summaries
  back as an earlier session's.
- **ACP permission prompts name a call the client has seen.** The client now
  gets the `tool_call` first, and the permission request uses the same id.

No public method was removed. A few changes can affect an existing host or
ACP client. Read the next section before upgrading.

## Check this before upgrading

**1. ACP: `tool_call` now arrives before `session/request_permission`.** For
a call that needs approval, the client used to get the permission request
first, under an id of its own, and then a second, unrelated `tool_call`. Now
the call is opened (`status: "pending"`, with the diff for a file edit), the
permission request reuses its `toolCallId`, and the call's later start is a
`tool_call_update` rather than a second `tool_call`. This matches the ACP
reference adapter and gemini-cli. A client that keyed its approval dialog on
the old order will see one call where it used to see two.

**2. A shell executor subclass sees an exception for a command that could
not start.** `LocalShellExecutor.run` used to return `returncode=-1` when
`Popen` failed. That is also what a SIGHUP-killed child reports, so the tool
said the command was killed by a signal. The foreground path now raises, as
the background path always did. A subclass that called `super().run()` and
read `-1` as "did not start" should catch the exception instead.

**3. A `guarded_get` client stand-in needs `build_request` and `send`.**
`guarded_get` / `guarded_get_async` now stream each redirect hop through
`client.build_request` + `client.send(stream=True)` instead of calling
`client.get`. A test double that implements only `get` needs the other two.
The returned response still has its body loaded.

**4. PowerShell CLIXML over 1 MiB reaches the model raw.** A stream with a
gap in it is shown as raw XML rather than unwrapped, because the unwrap would
join the elements on either side of the gap into one message.

## Shell output

**Each stream keeps its first and last 512 KiB.** `LocalShellExecutor.run`
used to hold every byte until the child exited: a command printing 400 MB
peaked at about 1 GB RSS. It now peaks at about 45 MB. Output up to 1 MiB a
stream is unchanged.

**The model sees both ends of a long output.** It gets a fifth from the
start and the rest from the end, the same split the result layer uses, so a
compiler's first error is no longer cut away in favour of its last. The gap
is marked where it is: `[... N bytes of output not kept ...]`.

**Every shell result stays within 40,000 characters.** The tool used to add
its headers and notices on top of a 40,000-character cut, so a large output
came back just over the result layer's threshold. The layer then saved the
already-cut text to `.agentao/tool-outputs/` and told the model it was the
full output. The budget now covers the whole returned string on every path:
normal, timeout, background start, and the macOS sandbox hint.

For hosts, `ShellResult` has four new fields, all defaulting to `0`:
`stdout_omitted_bytes`, `stderr_omitted_bytes`, `stdout_omitted_at` and
`stderr_omitted_at`. An executor that keeps everything needs no change.

**A `working_directory` the OS will not stat is refused.** A path that is too
long, or whose parent has no search permission, used to raise out of the
tool. It now returns `Error: working_directory '…' cannot be used: <reason>.`

## Network

**`web_fetch` reads at most 5 MiB, for at most 60 seconds.** It used to read
the whole response into memory, at every redirect hop: a 300 MB response took
the process to 707 MB RSS. Each hop is now streamed, a redirect's body is
released unread, and a declared `Content-Length` over the cap is refused
before any byte arrives. For hosts, `guarded_get` / `guarded_get_async` take
`max_body_bytes=` (default `None`, unbounded as before) and raise
`agentao.security.ResponseTooLargeError` past it.

**The model list is bounded.** The fetch behind `/model` and ACP
`session/list_models` now allows 10 seconds a try and one retry. Its error
names the failure (`HTTP 403`, a timeout, no connection) and leaves the
response body to `agentao.log`, instead of sending it to the ACP client.

## Turns, compaction and memory

**A Ctrl+C mid-stream keeps the text already shown.** History records
`<text>\n\n[Interrupted]`, so the next turn's model knows what it had said.
In markdown mode the CLI now shows that text too.

**Compaction honours the turn's cancel.** The summarizer's retry wait used to
run to the end after `agentao run`, ACP `session/cancel` or a host token
cancelled the turn. Three cancelled turns could also have opened the circuit
breaker. A cancel now stops the summarizer and leaves history untouched.

**A resumed conversation no longer sees its own summaries twice.**
Summaries are now written under the conversation's id, so after `--resume`,
`/sessions resume` or ACP `session/load` they are not injected again as an
earlier session's. Summaries written before this release keep their old
random ids, so resuming one of those older sessions still shows the
duplicate. A host that resumes sessions itself should call
`agent.memory_manager.archive_session(session_id)`.

## Sub-agents

**A sub-agent's `[agent n/N]` label no longer skips a number after a
rejected call.** The label and the ACP title stay the same for the whole
call. Only the display changed: the real iteration limit was never affected.

## Upgrading

```bash
pip install -U agentao
```

Check the four items at the top if you:

- have an ACP client that handles `session/request_permission`;
- subclass `LocalShellExecutor`;
- pass your own HTTP client to `guarded_get` / `guarded_get_async`;
- run PowerShell commands that write large CLIXML error streams.
