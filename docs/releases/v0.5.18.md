# Agentao 0.5.18

This release is about the prompt cache. An active skill's body used to be sent
on every request in the request-only tail, which is outside the provider's
prompt cache. It now goes into history once, and the tail carries a one-line
pointer (#552). The release also adds an opt-in switch that follows an MCP
server's tool-list changes, keeps hook-blocked prompts out of replay, and
fixes error handling on openai 3.38 and later, wake turns, concurrent
session saves and Responses overload retries.
Two changes behave differently on upgrade; see
[Behaviour changes](#behaviour-changes).

## Behaviour changes

- **An active local or plugin skill is a snapshot taken at activation**
  (#594). Its `SKILL.md` and resource list were read again on every request,
  so an edit took effect at once. Now an edit takes effect after
  `/skills activate <name>` again or `/skills reload` (which `/crystallize`
  runs).
- **`agent.messages` holds skill-state reminders** (#594, #597). Before the
  next model request, the runtime appends a user `<system-reminder>` that
  starts with `Skill loaded: "<name>"` and holds the skill's body, or
  `Skill no longer active: "<name>"` after a deactivation. Hosts that read
  `agent.messages` see them, and `LLM_CALL_STARTED`'s
  `n_system_reminder_blocks` counts them. ACP `session/load` does not show
  them to the client. This holds for MCP skills too (#597), so
  `/skills activate` of an MCP skill no longer appends its separate
  provenance note: the `Skill loaded` message carries the origin.

## Skill bodies in history (#552)

- **Local and plugin skills** (#594). Every way of activating a skill — the
  `activate_skill` tool, `/skills activate`, `spec.skills` in `agentao run`,
  a session restore — now puts the body into history once. The tail gives the
  skill's `Task:` and a pointer. Only each skill's latest `Skill loaded` or
  `Skill no longer active` message counts, so a compaction that removed the
  body makes the runtime append it once more, and a restored session that
  already holds it gets no second copy.
- **MCP skills** (#593, #597). While the model's latest `activate_skill`
  result still holds the skill's current block, the tail points at that
  result, and microcompaction keeps it whole. Otherwise the body goes into
  history as a `Skill loaded` message that ends with a line naming the MCP
  server. Compaction, the session save and a restore read that line as the
  message's origin, so the MCP gates still apply. A restore withholds the
  body and keeps the first line.
- **Measured** on one workload: `agentao run` with one local skill in
  `spec.skills`, DeepSeek `deepseek-flash`, 10 runs per version alternating,
  before `44502d73` and after `96cca5b7`. The medians:

  | | Before | After |
  |---|---|---|
  | Cache-miss tokens per request, excluding the first | 5,254 | 1,666 (−68%) |
  | Volatile tail per request (agentao's estimate) | 5,416 | 135 |
  | Cache hit share | 90.3% | 93.8% |

  The first request still misses, because it sends the body once. The MCP
  half was not measured separately. Details: issue #552.

## MCP

- **Opt-in: `"refresh_tools": true` follows a server's tool list** (#590). A
  `notifications/tools/list_changed` used to be ignored, so a tool the server
  added never reached the model and a removed one stayed callable. With the
  switch on, Agentao lists that server's tools again before the next model
  request, in the same turn too, and replaces only that server's tools. A
  re-list that fails, or takes longer than `min(10 s, startup)`, keeps the
  current tools with a warning. A server that needed login at startup loads
  its tools after `/mcp login`, without a restart. Off by default, because
  each change restarts the provider's prompt cache for the tool list.
- **Documented: on mcp 1.x, a cancelled or timed-out MCP tool call keeps
  running on the server** (#591). mcp 2.x sends `notifications/cancelled`;
  1.x sends nothing. Behaviour is unchanged.

## Fixes

- **Error classification works again on openai 3.38 and later** (#600).
  openai 3.38 (2026-10-26) dropped the error JSON from the text of an API
  error, and Agentao read that text. On the `openai-responses` wire, a
  gateway that refuses `include: [reasoning.encrypted_content]` only through
  `param` or a pydantic `loc` made every request fail with a 400, and an
  overflow named only by its `code` was missed. Agentao now reads the SDK's
  error body too. 0.5.17 is affected when openai 3.38 or later is installed,
  which a fresh install gets: upgrade to 0.5.18.
- **A prompt a `UserPromptSubmit` hook blocks or stops is not written to
  replay** (#592). Its `user_message` row has an empty `content` and
  `withheld: "hook_blocked"` or `"hook_stopped"`. An allowed prompt's row now
  comes after the hook's `plugin_hook_fired` row. `TURN_BEGIN` still carries
  the raw input, so a host that subscribes to events may still receive it.
  The replay schema stays 1.6.
- **Ctrl+C on a background wake turn stops further wakes** (#589). An
  interrupted wake turn now pauses the wake, and any line you submit starts it
  again.
- **Two processes saving sessions into one project no longer fail** (#589).
  Rotation ignores a file another process already removed, and each save
  writes its own temp file, so a session file only ever appears whole.
  Session files are now written mode `0600` on POSIX.
- **The `openai-responses` wire retries an overload reported inside the
  stream** (#589): `server_is_overloaded`, `slow_down` and
  `policy_capacity_unavailable`, as it already retried HTTP 503 and 429.
