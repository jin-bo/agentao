# Agentao 0.5.14

This release hardens the shell sandbox and the read-only search tool, makes
mixed tool batches run in order, and fixes several turns that ended wrongly:
a re-read after an edit stopped as a doom loop, a hook-blocked prompt counted
as an answer, and a corrupt `memory.db` failed every turn. Most fixes come
from a review of the codex changes of 2026-10-13. Six changes behave
differently on upgrade; see [Behaviour changes](#behaviour-changes).

## Behaviour changes

- **A project `.agentao/sandbox.json` is ignored.** The sandbox reads
  `~/.agentao/sandbox.json` only. A file checked into a repository, or written
  by a sandboxed command, could turn the sandbox off for the next session.
  Agentao logs a warning naming the ignored file, and `/sandbox status`,
  `agentao doctor` and `agentao config validate` report it. Move project
  settings to `~/.agentao/sandbox.json`, or pass `sandbox_policy=` in code.
- **A sandboxed command cannot write `~/.agentao` or the user `profiles_dir`**,
  whatever the workspace. The profile is now passed inline and ends with a
  deny rule for those paths.
- **A tool batch runs in parallel only when every tool in it is read-only.**
  One write, shell command, untrusted MCP tool or foreground sub-agent call
  makes the batch run one call at a time, in the order the model gave.
- **A turn that a `UserPromptSubmit` hook blocks or stops is not an answer.**
  `agentao run` exits `1` with error type `hook_stop` instead of `0`, and a
  `/goal` is blocked after three such turns in a row.
- **A compaction summary cut off at the token limit is refused.** History is
  unchanged and the failure counts toward the circuit breaker. The API-overflow
  path still keeps it, with a warning.
- **`Agentao.close()` cancels the background sub-agents it launched** and
  waits up to 5 s for them. A launch after `close()` raises
  `BackgroundOwnerClosedError`.

## Security

- **The sandbox runs `/usr/bin/sandbox-exec`**, not the first `sandbox-exec`
  on `PATH`, which a sandboxed command could plant in `.venv/bin`.
- **`search_file_content` passes `--no-config` to ripgrep** and
  `-c core.fsmonitor=false` to git. A project `.env` setting
  `RIPGREP_CONFIG_PATH`, or a repository's own `core.fsmonitor`, could run a
  command from this read-only tool without confirmation.
- **The LLM key in use is scrubbed from child processes by value**, whatever
  variable holds it. Before, a `/provider` switch or a host `api_key=` read
  from its own variable left the key in the environment of shell commands,
  hooks and MCP servers. Values under 16 characters are not recorded.
- **`/sessions resume` ends the "2 = allow all this session" grant.** The
  resumed conversation no longer runs every tool without asking.

## Tools and turns

- **Re-reading a file after editing it no longer ends the turn as
  `doom_loop`** (#543). A potential write that is new in the turn clears the
  identical-call counts, so `read_file` or the same `pytest` after an edit is
  not a loop. An identical call with no new write in between still stops the
  turn on the third call.
- **`replace` keeps a CRLF file CRLF.**
- **Ctrl+C inside a tool ends its events with `cancelled`**, so ACP, replay
  and the CLI no longer see a call that started and never ended.

## Memory

- **A corrupt `memory.db` no longer fails every turn.** The turn runs without
  that store's memories, and the CLI shows a notice. A store that could not be
  opened also gets a notice now, not only a log line.

## Documentation

- The developer guide's non-interactive chapter lists the `hook_stop` error
  type and exit code.
- The guide explains that hooks do not run inside sub-agents, and what that
  means for a `PreToolUse` block.
- The `sandbox.json` examples show the real fields.

## For hosts

New public names, each from a fix above:
`MemoryManager.take_store_problems()`, and in `agentao.agents.bg_store`:
`BackgroundOwner`, `BackgroundOwnerClosedError`,
`BackgroundTaskStore.close_owner()` and the keyword-only `owner=` on
`BackgroundTaskStore.register()`.

## Upgrading

```bash
pip install -U agentao
```

Check the six [behaviour changes](#behaviour-changes) above. See
`CHANGELOG.md` for the full list.
