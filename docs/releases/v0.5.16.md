# Agentao 0.5.16

This release is about `agentao run` on long batch jobs. A new interaction
policy, `deny`, lets a run go on when one tool call needs an approval nobody
can give: the model is told no and can take another route, instead of the
whole run ending. Each denial is listed in the result and attributed to its
call. `search_file_content` now finds files that git does not track. Two
changes behave differently on upgrade; see
[Behaviour changes](#behaviour-changes).

## Behaviour changes

- **`permission_required` names the rule that asked.** The error of a run that
  ends on a call needing approval now carries `matched_rule` when an engine
  rule asked, also under the default `reject`. The field is left out when no
  rule matched. A consumer that ignores unknown keys needs no change.
- **`NonInteractiveTransport` pairs a confirmation with its call by the
  `TOOL_CONFIRMATION` event**, not by tool name. Before, the ids and rules fed
  in through `queue_ask` were matched to confirmations by tool name in arrival
  order, which could hand two calls of one tool each other's rule.
  `agentao run` itself is unaffected, because the runner emits the event. A
  host that feeds `queue_ask` and then calls `confirm_tool` directly, or wraps
  the transport without forwarding `emit(TOOL_CONFIRMATION)` and the
  `confirm_tool` after it on the same thread, now gets `tool_call_id: null`
  and no rule.

## `agentao run`: deny instead of abort

- **`--interaction-policy deny`** (or `interaction_policy: deny` in a spec).
  Under `reject`, still the default, one tool call that needs approval ends
  the run with `permission_required`, exit `3`. That includes a harmless shell
  command just outside the read-only allowlist, such as `true` or
  `echo "noop"`. The model never sees the refusal, and the steps the run had
  not reached yet (a closing log or index entry, say) are left undone. Under
  `deny` the call is not run. The model gets a result that says approval is
  unavailable in non-interactive mode, tells it not to retry the call, and
  allows an alternative the current permission rules permit. The turn goes on.
- **`--max-denials N`** (spec `max_denials`, default `5`) bounds it. The first
  `N` calls are declined back to the model. Call `N + 1` ends the run as
  `reject` does, and the other calls of its batch are cancelled. `0` makes
  `deny` act as `reject`. `max_denials` without `deny`, a negative value or a
  boolean exits `2`.
- **`denials` in the result** lists each declined call (`tool_name`,
  `tool_call_id`, `matched_rule`), on success and on failure. Text mode
  writes one stderr line per denial. A foreground sub-agent's denial has its
  own `tool_call_id` and no `matched_rule`.
- **Exit `0` under `deny` means the model gave a final answer.** It does not
  mean the task is complete: a step the model wanted may be in `denials`, and
  nothing is rolled back. Check `denials` before you treat a result as done.
- **What `deny` does not change:** `ask_user` still ends the run
  (`interaction_required`). So does a call that a rule or `read-only` mode
  denies (`permission_denied`). A confirmation the MCP Skills gate asks keeps
  the plain "not approved" result, which offers no alternative. An interactive
  "no" keeps its wording.

## Search

- **`search_file_content` finds untracked files and searches ignored
  directories in a git work tree** (#563). In a git repository it searched
  with `git grep`, which reads tracked files only, so a file the agent had
  just written and not yet `git add`ed was never found, and a search inside a
  gitignored directory always answered "No matches". `git grep` now also
  searches untracked files. When `.gitignore` ignores the directory being
  searched, the tool searches it with ripgrep or the Python scan instead. A
  search from a directory that is not ignored still skips ignored files.

## For hosts

New public names: `agentao.transport.record_decline()` and
`APPROVAL_UNAVAILABLE`, which tell the runner a confirmation was declined
because nobody could answer it. `NonInteractiveTransport` takes `policy=` and
`max_denials=`, and has `denials` and `record_rejection()`. The host API
reference has two new sections: "Saying why a confirmation was declined" and
"Wrapping `NonInteractiveTransport`".

