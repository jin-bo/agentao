# Agentao 0.4.26

A **prompt-caching release**, plus one fix for anyone whose account can run
out of quota. The system message is now byte-identical across the turns of a
session, which it never was; explicit cache breakpoints are available for
endpoints that honour them, off by default; and a 429 for exhausted quota
fails at once instead of being sent four more times.

## The system message is now a stable prefix

Skills, todos, dynamic memory recall and the plan prompt left the system
message. They ride a trailing `user` message assembled per request, wrapped
in one `<system-reminder>`, and that message is **never** appended to
history — so it reaches no session file, no replay record and no compaction.

The reason is provider prompt caching. `<memory-context>` is scored against
the current user message, so it changed every turn; and the system message is
the head of the cached prefix, so every change invalidated the cache covering
the **entire history**. A `todo_write` did the same.

Measured on the agentao repository itself: the system message is 2,350 tokens
and byte-identical turn to turn, against a tail of about 1.8k tokens — nearly
all of it the available-skills catalogue — that is re-sent uncached on each
request. **That is a measurement of request shape, not of a bill.** No billed
cache-hit comparison against a real endpoint has been run yet, so compare both
numbers against your own deployment before reading this as a saving; a
project with no skills on disk has a tail of a few dozen tokens.

Three consequences worth knowing:

- **The tail is rebuilt per request, not per turn.** A `todo_write` the model
  makes in one tool iteration is visible to the next one. Before, it waited
  for a system-prompt rebuild.
- **A turn's first request now ends in two `user` messages in a row.** Chat
  Completions allows it, and agentao already produced that shape through
  background notifications, but an endpoint that enforces strict role
  alternation will reject it.
- **Compaction thresholds are unchanged in intent.** The token anchor is
  recorded against the persistent history with the tail's estimate subtracted
  out, so the tail is not double-counted into an early compaction.
  `get_usage_stats()['estimated_tokens']` still reports the request total, and
  `token_breakdown` gains a `tail` bucket so those tokens do not read as
  having vanished.

A literal `</system-reminder>` inside a memory value or a skill description is
neutralized before wrapping, so content the model or a server authored cannot
close the wrapper early.

## Opt-in explicit cache breakpoints

`LLM_PROMPT_CACHE=anthropic` — or `prompt_cache=` / `prompt_cache_ttl=` on
`Agentao(...)` and `LLMClient(...)` — puts at most **three** Anthropic-style
`cache_control` markers on each agent-turn request: the system message, the
last tool definition, and the end of stable history. The fourth breakpoint
slot is left free for the endpoint's automatic caching. `LLM_PROMPT_CACHE_TTL`
is `5m` (the default) or `1h`.

**Off by default, and never inferred from a base URL or a model name.**
agentao verified that the OpenAI SDK forwards the key unchanged (openai
2.24.0). It did not verify that any particular gateway honours it. Before
turning it on, check three things on your endpoint:

1. It forwards `cache_control` rather than answering 400.
2. It accepts a `role: "tool"` message whose `content` is an array — marking
   the end of history can promote a tool result's content to that shape.
3. Its `usage.prompt_tokens` **includes** cached tokens. An endpoint that
   reports the figure net of cache reads makes agentao's context estimate far
   too low, and compaction stops triggering.

What the implementation guarantees:

- Markers are copy-on-mark and applied at the wire boundary, so they never
  enter history, session files, the replay record or compaction, and cannot
  accumulate across turns.
- Markers a host placed itself count against the three and are never
  overwritten. Anthropic's caching documentation requires longer-lived cache
  entries to precede shorter-lived ones, so a site that would break that order
  against a caller's marker is skipped rather than re-timed, and an
  unrecognised `ttl` suppresses agentao's markers entirely.
- An unknown `LLM_PROMPT_CACHE` value raises at startup rather than silently
  disabling the thing it was set to enable.
- `/provider` to a different base URL drops the markers — the setting asserts
  something about one endpoint. A credential rotation against the same
  endpoint keeps them. Sub-agents inherit the setting.

## Fixed: a 429 for exhausted quota is no longer retried

Every 429 was retried as a rate limit, so a request from an account that was
out of quota, credit or spend allowance was sent four more times, with 22–29
seconds of backoff in between — up to the 60-second budget when the provider
sends `Retry-After` — before the same error surfaced.

The retry policy now reads the error's `code` and `type`.
`insufficient_quota`, `credit_balance_exhausted`,
`organization_spend_limit_exceeded`, `project_spend_limit_exceeded` and
`organization_usage_limit_exceeded` are not retried, on the streaming and
non-streaming paths alike. The match is exact: a provider that reports
exhausted quota some other way is still retried as before, and every other
429 — including one with no JSON body — still waits. The error raised, the
`llm_error` turn classification and `agentao run`'s exit code are unchanged. A
`/goal` loop on an exhausted key now sends one request per continuation
instead of five before its no-progress guard stops it.

## Who needs to do something

- **Hosts or tests that read todos, skills, recall or the plan prompt out of
  the system prompt.** `_build_system_prompt()` now returns the stable half
  only; the volatile half is `_build_volatile_tail()`. Both are private, but
  if you were reading them, you need the second call.
- **Deployments behind an endpoint that enforces strict `user` / `assistant`
  alternation.** The trailing `user` message will be rejected there. Chat
  Completions itself does not require alternation.
- Everyone else: nothing. Prompt-cache breakpoints stay off until you set
  them.

## Compatibility

No public API removed and no configuration migrated. Two keyword-only
constructor arguments (`prompt_cache`, `prompt_cache_ttl`) and two
environment variables (`LLM_PROMPT_CACHE`, `LLM_PROMPT_CACHE_TTL`) are new.
The model-visible instructions are the same text as before, delivered in two
messages instead of one.
