# Agentao 0.4.21

A **hook-contract release**. Agentao's plugin hooks and Claude Code's have
always looked like the same feature; a three-way comparison found nine places
where they are not, and one deviation upstream of all of them: a `hooks.json`
copied out of a working Claude Code setup parsed to **zero rules**.

It did not fail loudly. It produced one warning that named the wrong thing —
`Unknown hook type '' under 'PreToolUse'` — because the entry it was reading is
a matcher group, not a handler, and the file had never written a `type` key at
that level. So the diagnosis pointed away from the actual mismatch: the official
file nests four levels, event → matcher group → `hooks[]` → handler, with a
**string** matcher, and agentao read handlers straight out of the event array
with a dict matcher.

The headline:

- **Both shapes now parse, chosen per file.** `agentao-v1` (the flat shape) is
  **frozen** and behaves exactly as before. `claude-code@profile-1` is new. A
  copied file carries no marker to gate on, so the parser reads the entries
  themselves.
- **The profile is enumerated, not aspirational.** Eight events, and within
  them a listed set of fields. A key the profile does not implement is
  **ignored with a one-time diagnostic naming it**, never a schema error — a
  hook written for a newer Claude Code keeps working, and its author is told
  which key had no effect instead of guessing.
- **Hook output is bounded.** It could previously return unbounded stdout
  straight into the context window. Two tiers now: 8 MiB raw capture, 10,000
  characters per delivered channel, overflow spilled to disk with credentials
  redacted before the bytes land.
- **A hook can end a turn from inside a tool worker.** `PostToolUse` hooks run
  three frames below anything that could act on a decision, so `continue: false`
  there was computed and dropped.
- **Thirteen defects found by a post-merge review**, two of them
  security-relevant. The suite stood at 4590 before those fixes and 4590 after:
  no test in the repo distinguished fixed from broken. They ship with seventeen
  that do.

## Measured, not inferred

Four of the ten design gates — six rows in the closure record — were settled by
driving a real `claude` 2.1.251 headlessly in throwaway project directories.
Three of those probes **corrected the plan** rather than confirming it:

- The matcher is an **anchored full match**, not the unanchored regex the plan
  had assumed for its whole life. `ead` does not match `Read`. An unanchored
  implementation would have fired hooks on tools their author never named.
- `PostToolUseFailure` **honors** `decision` — the narrow reading was reversed.
  A control run proved the mechanism is the recognized field and not echoed
  stdout: an unrelated key reached the model zero times.
- `SessionStart` / `SessionEnd` matchers compare against `source` and `reason`.
  Returning the empty string for them, as the first implementation did, made
  every non-`*` matcher on those events silently dead.

A sixth probe, after the review, settled the empty matcher: `""` is a wildcard
alongside `*`, confirmed with both a positive and a negative control.

The probe record, including what each finding does **not** prove and two false
results it produced before it produced true ones, ships in the repository at
`docs/reference/hooks-probe-2.1.251.md`.

## Breaking changes

One, with three consequences. All of them are the same event: **configuration
that was inert becomes live.**

If a plugin in your tree ships a Claude-shaped `hooks.json`, it did nothing
before this release and runs now. Check for it before upgrading if that
matters:

```
find . -path '*/hooks/hooks.json'
```

The three consequences, all confined to `claude-code@profile-1` rules:

1. **`agentao run` can now exit 1 where it exited 0.** A hook returning
   `continue: false` ends the turn, which classifies as a turn without a
   complete answer — `error.type` and `error.reason` are both `hook_stop`.
   Branch on `reason`, not on `message`.
2. **A `""` matcher now matches everything.** It matched nothing before, so a
   config that spells the wildcard that way was dormant.
3. **`PreToolUse` fires on a call the permission engine already denied.**
   Observation and authority are separate: an audit or notifier hook was blind
   to exactly the calls it exists to record. The verdict stays `DENY`.

`agentao-v1` files are unaffected in all three cases — the contract is frozen,
and every behaviour change is gated on it with both halves tested.

## The two security fixes

Both were found reviewing the merged implementation, and neither was reachable
from the test suite.

**An unusable `updatedInput` re-decision ran the original command.** A
`PreToolUse` hook that rewrites a call's input has already said the original
must not run. When the permission re-decision could not be computed, the
rewrite was dropped and the original executed under the verdict computed for
it. The call is now denied — neither the rewrite nor the original. There is a
third state here that is easy to miss: the first fix attempt chose "drop the
rewrite", which is the same unsafe outcome reached from the other direction.

**Hook-authored context reached the model without the Unicode-tag strip.** It
was appended to the tool message after the strip, leaving the one model-bound
string on that path that skipped the boundary — and hook text is routinely a
relay of something the hook read: a fetched page, an MCP result, a file. That
is precisely the carrier the tag defense exists for.

## What this does not do

Agentao implements **8** of the reference's events, and the gap is not a defect
on either side — it is what "profile" means. The event list, the field list and
the per-event disposition are all written down, so the boundary is checkable
rather than discovered at runtime. Sub-agents fire no hooks at all; that is
stated in the design rather than left to be found.

There is no pre-execution input validation: agentao does not check a tool's
arguments against its schema before running it, so a rewrite the tool cannot
accept fails inside the tool rather than being refused earlier. Upstream refuses
it. The outcome that matters is the same — the original never runs — and the
difference is the error surface.

## Upgrading

`pip install -U agentao`. If no plugin in your tree ships a
`hooks/hooks.json` in the Claude shape, nothing changes. If one does, it starts
running: read it first.

The full field-by-field reference, both schemas, the output limits and the
precedence rules are in `docs/reference/configuration.md` section 11.
