# Agentao 0.5.11

This release is mostly fixes: security hardening for `web_fetch` and the
credential scanner, shell and cancellation fixes, and several MCP and model
fixes. Three of them change behaviour on upgrade; see
[Behaviour changes](#behaviour-changes). It also adds `oauth.profile` for MCP
servers.

## Behaviour changes

- **Writes to credential files ask in `workspace-write`.** `write_file` and
  `replace` on `.env`, `.env.*`, `*.pem` or `*.key` now ask first, like writes
  into `.git` and `.agentao`. `.env.example`, `.sample`, `.template` and
  `.dist` are still allowed. `full-access` is unchanged, and a project rule
  that allows the path still wins.
- **An unset or empty variable in an MCP server's `headers` or
  `oauth.client_secret` keeps that server from connecting.** It used to
  expand to an empty string. `"Authorization": "Bearer ${TOKEN}"` with `TOKEN`
  unset sent `Bearer ` and turned OAuth off. The server and `/mcp login` now
  report an error that names the variable. In `env` and `args`, an unset
  variable still expands to an empty string, now with a warning.
- **Some MCP tool names change.** A name over 64 characters failed every
  request on Chat Completions. It is now cut and ends in an 8-character hash
  of the original server and tool names. That hash is the same on every
  connect. A server or tool name with non-ASCII characters gets the same
  suffix. If a permission rule or a sub-agent `tools:` list names such a tool,
  update it to the registered name, which `agentao.log` records
  (`Registered MCP tool: …`). Two tools that map to one name (`my-srv` and
  `my_srv`) are no longer both registered: the first keeps the name, and the
  second is left out with an error in the log. All other names are
  unchanged.

## Security

- **`web_fetch` refuses cloud metadata endpoints in every encoding.** Before
  this release, Azure WireServer (`168.63.129.16`), Oracle Classic
  (`192.0.0.192`), and `169.254.169.254` written as RFC 8215 NAT64, ISATAP or
  IPv4-compatible IPv6 all got through. The policy no longer depends on the
  Python version's `ipaddress.is_global`. `AGENTAO_WEB_FETCH_ALLOW_CIDRS` opens
  a metadata endpoint only when it names that exact address.
- **Credential redaction catches eight more shapes**: GitHub fine-grained
  tokens, Slack app tokens, Stripe keys, Google OAuth client secrets, PGP
  private keys, and private keys pasted without their `END` line. Scanning
  repeated key headers is no longer quadratic.
- **A fetched page can no longer write a sub-agent a second task.** Text
  quoted in a sub-agent's parent context can no longer start a `[user]:` or
  `[Your Task]` line.

## Shell and cancellation

- **A shell command that prints a line now and then is no longer killed as
  idle.** Before this release, output under 4 KiB reset neither the inactivity
  timeout nor the live output.
- **Cancelling a turn stops a running shell command or MCP call.** That
  covers Ctrl+C, ACP `session/cancel` and `CancellationToken.cancel`. The
  command's process tree is killed, and the result keeps what the command had
  printed. An MCP call is abandoned; on mcp 2.x the server then gets
  `notifications/cancelled`.

## Models and MCP

- **Claude Fable 5.1, Opus 5.5 and Sonnet 5.5 sessions no longer end when the
  system prompt or tool list changes.** On accounts created on or after
  2026-08-31, the API rejects a replayed thinking block once the prompt or
  tools change. agentao now asks the API to drop the stale block instead.
- **Thinking text is kept from Ollama, newer vLLM and OpenRouter**, which
  send it as `delta.reasoning`.
- **A context overflow from vLLM, Bedrock Mantle or Anthropic now triggers
  compaction**, instead of ending the turn as an error.
- **An MCP tool call is no longer sent twice when its connection drops.** The
  call returns an error saying the result is unknown.
- **`web_fetch` returns plain text, JSON and source files as they are.** It
  used to parse them as HTML, so `if (a<b && c>d)` became `if (ad)`.
- **A `---` inside a frontmatter value no longer ends the block** in
  `SKILL.md`, agent definitions and plugin files.

## New: `oauth.profile`

Two `mcp.json` entries that point at the same server URL can now log in as
two accounts: `"oauth": {"profile": "<name>"}`. Entries without a profile are
unchanged, and existing logins keep working.

## For hosts

- **`ShellRequest.cancellation_token` and `ShellResult.cancelled` are new.**
  Both have defaults, and `cancelled` is the last field. A custom
  `ShellExecutor` that ignores them works as before.
- **`AgentCancelledError` takes `partial_output=`.** A sync tool that raises
  it while the turn is cancelled is reported as cancelled. A tool that raises
  it from a token of its own is reported as an error.
- **Unanswered `tool_calls` in history a host wrote are answered when a turn
  starts.**

## Upgrading

```bash
pip install -U agentao
```

Check the three [behaviour changes](#behaviour-changes) above. See
`CHANGELOG.md` for the full list.
