# Agentao 0.5.4

This release fixes three areas:

- **Model requests survive a dropped connection.** A turn no longer fails
  because a proxy closed the stream before any text arrived.
- **Read-only mode holds on every entry path**, including ACP, embedding and
  sub-agents. Every permission-mode switch is now recorded.
- **ACP clients see what the agent is doing.** They get the whole output of a
  streaming tool, a file edit as a diff, and an error when the model call
  fails.

Three of these changes can affect an existing host or ACP client. Read the
next section before upgrading.

## Check this before upgrading

**1. Read-only mode now applies when only the engine's mode is set.** Some
hosts set read-only through the permission engine:

- ACP `session/set_mode` with `modeId: "read-only"`;
- an embedded host calling `permission_engine.set_mode(PermissionMode.READ_ONLY)`;
- a sub-agent deciding with a snapshot of such an engine.

Before this release, those hosts did not really get read-only.
`write_file`, `replace` and `run_shell_command` fell through to ASK, which
the default transport approves. `save_memory` ran without asking at all.
Only the CLI and `agentao run` blocked them.

Now every tool whose `is_read_only` is `False` is denied before the engine is
consulted. That includes your own tools. A `rules=` `allow`, a custom
engine's decision, or an ASK the transport would approve no longer lets one
run. If you used engine-only read-only to block the built-in writes but keep
your own business tools running, switch to `workspace-write` and add `deny`
rules instead:

```python
from agentao import Agentao
from agentao.permissions import PermissionEngine, PermissionMode

# User rules are evaluated before the workspace-write preset, so these win,
# and your own tools are still decided by the engine.
engine = PermissionEngine(
    project_root=workdir,
    rules=[
        {"tool": "write_file", "action": "deny"},
        {"tool": "replace", "action": "deny"},
        {"tool": "run_shell_command", "action": "deny"},
        {"tool": "save_memory", "action": "deny"},
    ],
)
engine.set_mode(PermissionMode.WORKSPACE_WRITE)
agent = Agentao(working_directory=workdir, permission_engine=engine)
```

Both `examples/ticket-automation` and `examples/saas-assistant` were moved to
this pattern.

**2. Over ACP, a failed model call is now a JSON-RPC error.** It used to
answer `{"stopReason": "end_turn"}`. It is now error `-32603`, with the turn's
`[LLM API error: …]` notice as `message` and `data: {"reason": "llm_error"}`.
A client that expected a successful result will see an error instead.

ACP v1 has no stop reason for "the model call failed". Reporting a provider
outage as `end_turn` told the client the turn ended normally, which is the
same turn that makes `agentao run` exit non-zero. gemini-cli handles it the
same way. Nothing else changes: a turn that produced no output still ends
with `end_turn`, and a cancel still wins over a failure.

**3. The ACP host schema grew.** `docs/schema/host.acp.v1.json` was
regenerated, with three changes:

- `AcpToolCallContentEntry` is now a union of `content` and `diff`.
- `AcpSessionUpdateToolCall` has an optional `content`.
- The `kind` enum has ACP v1's ten values instead of six.

Update any client code that switched on the narrower enum, or that assumed
every content entry is text.

Also removed: `MAX_TOTAL_RETRY_SECONDS` (see below). A host that patched it
has nothing left to patch.

## Model requests and network failures

**A connection that drops while the response is streaming is retried.**
Before the response arrives, both SDKs wrap a network failure as
`APIConnectionError`, and Agentao always retried that. After the stream has
opened, they don't:

- `openai` 2.x passes the raw `httpx` exception through;
- `anthropic` passes the raw `httpx2` one through.

Agentao treated those raw errors as permanent. So the everyday
`RemoteProtocolError: peer closed connection without sending complete message
body`, which is what you get when a gateway closes an idle stream, ended the
turn even when nothing had been shown. Timeouts, network errors and
`RemoteProtocolError` are now retried on all three wires.

**A stream that stops before its final event is retried too.** On
`anthropic-messages` and `openai-responses`, the final event is required.
When the connection closed cleanly before it, Agentao used to return what it
had so far as a finished answer. That included a tool call whose arguments
were cut off mid-JSON, and the runtime then ran it. It is now retried, and
the turn fails if every attempt is cut off. Chat Completions is unchanged,
because providers there often omit the finish reason legitimately.

**Retries are limited by count, and wait longer.** A request is tried up to 5
times, so there are 4 retries. The waits double from 7.5 s: 7.5, 15, 30, then
60 s, each plus up to 30% jitter and never more than 60 s. A `Retry-After`
header is honoured up to the same 60 s. The old 60 s total budget is gone. It
started counting before the first attempt, so a request that hung until the
SDK's read timeout had already used it up and was never retried. The cost is
at the short end: even a brief blip now waits 7.5 s before its first retry.

**The CLI says why it is waiting:**

```
⟳ Reconnecting… 1/4 (RemoteProtocolError; retrying in 7.8s)
```

Hosts get the same information as a new event, `EventType.LLM_RETRY`, sent
before each wait:

```json
{"retry": 1, "max_retries": 4, "delay_s": 7.8, "reason": "RemoteProtocolError"}
```

`reason` is `status=<code>` or the exception class name, never the
provider's message. The event comes from a new keyword-only `on_retry=`
callback on `LLMClient.chat()` / `chat_stream()`.

**A cancel stops the retries.** `chat()` now accepts `cancellation_token=`,
and the wait checks it. That matters for Gemini and for providers that
reject streaming, since both go through `chat()`. A cancel is also honoured
when the wait is zero (`Retry-After: 0`). Before, that case sent one more
request after the cancel.

Nothing changes once text has reached the host. A retry would show that text
twice, so a failure after that point still raises.

## Read-only mode and mode switches

**Read-only mode allows `activate_skill` and `todo_write`.** Both change only
the current session, so a read-only session or sub-agent can load a skill and
track its steps. `save_memory` is still denied, because it writes to disk and
outlives the session.

**`Agentao.set_permission_mode(mode, *, cause="host")`** is the supported way
for a host to change permission mode. Read-only has two switches, the engine's
mode and the runner's flag, and `engine.set_mode` alone moves only one of
them. The new method moves both and returns the previous mode.

**Every mode switch is recorded**, whichever path made it. Each emits
`PERMISSION_MODE_CHANGED`, and a read-only flip also emits
`READONLY_MODE_CHANGED`. The `cause` field says where the switch came from:

| `cause` | Where |
|---|---|
| `cli` | `/mode` |
| `acp` | ACP `session/set_mode` |
| `run` | `agentao run --permission-mode` |
| `host` | `Agentao.set_permission_mode` |
| `cli-allow-all` | answering "2" (yes to all) at a confirmation prompt, which moves the session to full-access |
| `cli-plan-implement` | `/plan implement` leaving read-only |

The last two used to record nothing at all, so a jump to full-access left no
trace in a replay. `/replays show` now prints the `cause` too.

## ACP

**A streaming tool's output arrives whole.** ACP v1 says a
`tool_call_update` replaces its `content` rather than adding to it. Agentao
sent each chunk as the whole collection, so a client kept only the last
chunk. When a shell command failed, the final `Error: …` erased the output
that explained why.

Each update now restates the whole output, and an error appears beside it.
To keep the traffic bounded, an update goes out every 4,000 characters, and
the client's copy keeps at most 16,000 characters (the start and the end,
with a count of what was left out). The model and replay still get the full
output.

**A file edit is sent as a diff.** A `replace` or an appending `write_file`
now opens its `tool_call`, and its `session/request_permission`, with a
`diff` entry. The client can render the change for approval instead of a raw
argument dict. `session/load` replays the edit the same way. A `write_file`
that overwrites a whole file sends no diff on purpose. The transport can't
tell whether the file already exists, and a diff with no old text would show
an overwrite as a brand-new file.

**Tool kinds are correct.** The tool-name → `kind` table listed tools Agentao
has never had, so `replace` and `search_file_content` were reported as
`other`. It is now rebuilt from the real tool list, and a test keeps it
complete.

## Upgrading

```bash
pip install -U agentao
```

No public method was removed. Check the three items at the top if you:

- set read-only through the permission engine;
- have an ACP client that handles a failed turn;
- code against the ACP host schema.

A host that monkeypatched `MAX_TOTAL_RETRY_SECONDS` should drop the patch.
