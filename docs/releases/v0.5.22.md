# Agentao 0.5.22

`web_fetch` gets a third opt-in fallback, DeepSeek's Fetch API. Read-only
mode now says why it blocks an MCP tool that its server marks read-only, and
no `web_fetch` error path reports a blank error any more. Nothing changes
unless you opt in, apart from wording: two messages gain a sentence.

## DeepSeek fallback for `web_fetch`

```bash
AGENTAO_WEB_FETCH_FALLBACK=deepseek
```

When a page needs JavaScript or the direct fetch fails, the URL goes to
DeepSeek's Fetch API (`POST https://api.deepseek.com/v1/tools/fetch`), which
fetches it server-side and returns Markdown.

- It is opt-in, like `jina`. The tool description and the result's
  `Fallback:` line say where the URL went.
- It reuses `DEEPSEEK_API_KEY` under the `web_search` rule: only when
  `DEEPSEEK_BASE_URL` is an `https` URL on `api.deepseek.com`. Without such
  a key there is no fallback, and the tool description says so.
- A target the URL policy blocks never reaches it. A URL with credentials in
  it is never sent, and a URL over the API's 8,192 characters is refused
  before the request. The response is capped like the other paths.
- DeepSeek bills each successful fetch.

Checked live against the DeepSeek API on 2026-11-15, through a real
`agentao run`: the model got the page through the fallback, and the key does
not appear in `agentao.log`.

## Read-only mode and untrusted MCP servers

An MCP server's `readOnlyHint` counts only when the server has
`"trust": true` in `mcp.json`. Read-only mode therefore blocks an untrusted
server's tools even when the server marks them read-only. The Tavily MCP
server, for example, marks all 5 of its tools read-only, and without trust
`tavily_extract` was blocked with no reason given.

- The block message now adds that the mark counts only with `"trust": true`,
  and that trust also lets the server's tools not marked destructive run
  without confirmation. The sentence is fixed text, and it appears only for
  a tool the server marks read-only.
- `/mcp list` adds a line under a connected, untrusted server that marks
  tools read-only:

  ```text
  ● tavily http 2025-11-25 — connected, 5 tool(s), resources
    5 tool(s) marked read-only; the marks count only with "trust": true
  ```

- Hosts get `McpTool.read_only_hint_ignored`,
  `agentao.mcp.tool.annotations_claim_read_only()` and a `read_only_marked`
  count in `McpClientManager.get_server_status()`.

Trust remains a real decision. To use such a server in read-only mode:

```json
{
  "mcpServers": {
    "tavily": { "type": "http", "url": "https://mcp.tavily.com/mcp/", "trust": true }
  }
}
```

## Fixes

- **`web_fetch` never reports a blank error.** A fallback that hit its
  whole-call timeout raised `asyncio.TimeoutError`, whose message is empty,
  so the error ended at the label's colon. The jina and playwright
  fallbacks, the direct fetch's `httpx` error and the catch-all now name the
  exception type when its message is empty.
