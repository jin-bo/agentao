# Agentao 0.5.0

Two things in one release, and they reach different people.

**A removal release.** Everything 0.4.x deprecated is gone — `agentao.harness`,
`agentao.session`, the eight callback kwargs on `Agentao(...)` — along with two
changes that **never warned**. If you embed Agentao, read *Who needs to do
something* before you upgrade.

**One opt-in addition**: a second wire protocol, `anthropic-messages`, so
Agentao can talk to Anthropic's own API natively instead of only through an
OpenAI-compatible endpoint. Nothing selects it for you. A deployment that does
not set `{PROVIDER}_API_FORMAT` behaves as it did on 0.4.27, with one visible
difference: `pip install` now also brings the `anthropic` SDK.

Upgrade guide: [`docs/migration/0.4.x-to-0.5.0.md`](../migration/0.4.x-to-0.5.0.md)
(`.zh.md` twin).

## Who needs to do something

Run your own test suite on **0.4.27** first, with warnings as errors:

```bash
python -m pytest -W error::DeprecationWarning
```

A clean run covers the first three rows. The next two cannot show up that way,
so grep for them.

| What | Symptom on 0.5.0 | Warned in 0.4.x? | Do this |
|---|---|---|---|
| `agentao.harness` | `ModuleNotFoundError` | yes, since 0.4.2 | Replace `harness` / `Harness` with `host` / `Host`. The objects are the same objects. |
| `agentao.session` | `ModuleNotFoundError` | yes, since 0.4.5 | Import from `agentao.embedding.sessions`. |
| The eight callback kwargs on `Agentao(...)` | `TypeError: unexpected keyword argument` | yes, since 0.4.5 | Pass `transport=`. If callbacks are what you have, `agentao.embedding.compat.build_compat_transport(...)` takes the same eight and is staying. |
| `project_root` on the seven `agentao.embedding.sessions` functions | `TypeError` naming `project_root` | **no** | Pass it. `None` is refused too — it used to mean the process cwd. |
| Positional arguments to `Agentao(...)` past the fifth | `TypeError: takes … positional arguments` | **no** | Pass everything after `max_tokens` by keyword. |
| Private attributes on `Agentao` (the replay views, three observability delegates) | `AttributeError` | no (private) | The migration guide §6 names the public replacement for each. |

Why the fifth row exists: the callbacks sat *between* `max_context_tokens`,
`permission_engine`, `transport` and `plan_session`. Deleting them alone would
have silently re-bound a positional caller's arguments to the wrong parameters.
Making everything after `max_tokens` keyword-only turns that into a loud
`TypeError` instead.

One thing the prompt lost: the "Reasoning Requirement" section. It had rendered
for no built-in surface since 2026-04 — only for a host passing
`thinking_callback=` directly — so the CLI, ACP and `agentao run` prompts are
unchanged. Its text is kept in the migration guide §7 for a host that wants it
back as its own instruction.

Not removed, despite an old promise: the public replay methods on `Agentao`, and
`replay_config=`. They have live callers and stay.

## The `anthropic-messages` wire

```bash
LLM_PROVIDER=CLAUDE
CLAUDE_API_KEY=sk-ant-...
CLAUDE_BASE_URL=https://api.anthropic.com      # the API root, no /v1
CLAUDE_MODEL=claude-sonnet-5
CLAUDE_API_FORMAT=anthropic-messages           # unset → openai-completions
```

Embedders pass keyword-only `api_format="anthropic-messages"` to `Agentao(...)`
or `LLMClient(...)`. The protocol is **named, never inferred** — not from the
URL, the provider name or the model name — and an unknown or not-yet-implemented
value fails closed rather than falling back. Conversation history keeps its
shape; only an outbound copy is translated, so sessions, replay and compaction
are untouched.

What it buys over an OpenAI-compatible endpoint:

- **Prompt caching that works and is reported.** With
  `LLM_PROMPT_CACHE=anthropic`, a 13-request session cost **78% less input**
  than uncached (159,843 of 177,771 prompt tokens read from cache). The same
  session over Anthropic's OpenAI-compatible endpoint accepts the markers but
  reports no cache fields at all, so their effect there cannot be read from the
  response.
- **Signed thinking blocks that survive a tool loop.** They ride the assistant
  message whole, beside the 500-character display copy, and go back verbatim.
- **Limits from the provider instead of from a rejection.** Before its first
  request for a model the client asks the Models API once. `max_tokens` clamps
  an oversized request instead of spending it on a 400; `max_input_tokens` can
  *narrow* the context window, never widen it; an endpoint without the route
  (compatible gateways mostly answer 404) changes nothing.

`/provider` carries the protocol: switching between a Chat Completions block and
a Messages block changes the wire with the credentials, clears what a model
switch clears (signed thinking included — it cannot be recovered), and keeps
`LLM_EXTRA_BODY`, naming its keys because they were written for the other
protocol. ACP's `provider_resolver` may return an optional `api_format`; omitted
means Chat Completions, exactly as before.

`/thinking <level>` works on both wires and writes a different field on each:
`reasoning_effort` on Chat Completions, `output_config.effort` on Messages
(`low | medium | high | xhigh | max`, or the levels the Models API marks
supported). A level the wire does not take is refused rather than stored.

### What is different on this wire, so it does not surprise you

- **`LLM_TEMPERATURE` and `/temperature` have no effect.** `anthropic` 1.6.0 has
  no `temperature` parameter on `messages.create` at all.
- **Extended thinking takes the adaptive form on current models.**
  `claude-sonnet-5` rejects `{"thinking": {"type": "enabled", …}}` with a 400;
  use `/thinking`, or `{"output_config": {"effort": "high"}}` in
  `LLM_EXTRA_BODY`. That model also returns its thinking *text* empty beside
  the signature, so there is nothing for the CLI to display.
- Both `chat()` and `chat_stream()` run over the streaming transport: the SDK
  refuses a non-streaming request at Agentao's default `max_tokens`.

### How far it has been verified

Against the real SDK over a scripted socket throughout, and then live against
`api.anthropic.com` with `claude-sonnet-5` and against one Anthropic-compatible
gateway. **Other Anthropic-compatible endpoints have not been tried.** No other
native protocol is implemented: `openai-responses` and `gemini-api` are reserved
names that fail closed.

## Also in this release

- The CLI's welcome banner shows the Agentao version.
- Anthropic's second context-overflow message
  (`input length and max_tokens exceed context limit: A + B > C`) is recognised
  on either wire, so overflow recovery runs instead of surfacing a raw 400.
- A foreground sub-agent no longer emits a `DeprecationWarning` at spawn.

## Compatibility

- **Breaking**: the removals and the two unwarned changes in the table above.
- **Dependencies**: `anthropic>=1.6.0` (with `docstring-parser`) is a new core
  dependency, imported lazily and never loaded on the default wire.
- **Unchanged**: every `agentao.host` model and both schema snapshots, event
  payloads apart from one additive key (`MODEL_CHANGED.api_format_changed`),
  configuration files, and `build_compat_transport`.
- **Additive**: `api_format=` on `Agentao`, `LLMClient`, `set_provider` and
  `reconfigure`; `context_manager.reported_limit` and a `reported_limit` key on
  `get_usage_stats()`; `LLMClient.model_input_limit` / `model_capabilities`.
- Production pins written as `agentao>=0.4.0,<0.5` do not admit this release —
  that is what the upper bound is for. Move to `>=0.5.0,<0.6` once your suite is
  clean.
