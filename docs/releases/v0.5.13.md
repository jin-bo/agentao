# Agentao 0.5.13

This release fixes how the CLI shows sub-agents and tool lines, makes every
config-file read and write safe against malformed, oversized and non-regular
files, fixes two memory-recall gaps, and adds `agentao --version`. The user
documentation now lives in the developer guide. Five changes behave
differently on upgrade; see [Behaviour changes](#behaviour-changes).

## Behaviour changes

- **`AgentManager.create_agent_tools` and `AgentToolWrapper` take
  `event_sink`, `confirm_tool` and `ask_user`** instead of six callbacks.
  Passing `confirmation_callback`, `confirmation_event_callback`,
  `step_callback`, `output_callback`, `tool_complete_callback` or
  `ask_user_callback` raises `TypeError`. These classes are not part of the
  host API; `build_compat_transport` and `Agentao(...)` are unchanged.
- **A directory or a named pipe at `permissions.json` stops startup** with
  `PermissionConfigError`. It used to read as a missing file, which dropped
  every rule in it.
- **An unknown top-level flag is refused.** `agentao --bogus`,
  `agentao -p "…" --jsno`, `init`, `plugin` and `skill` print
  `unrecognized arguments: …` and exit 2 instead of ignoring the flag.
- **Commands that write a config file refuse to overwrite one they cannot
  read.** `/replay on|off` and `/mode` leave a malformed or non-object
  `settings.json` unchanged, and `/mcp add|remove` do the same for `mcp.json`.
  Each prints why. `save_replay_enabled` raises `ReplaySettingsError` and
  `save_mcp_config` raises `McpConfigWriteError` in those cases.
- **`agentao.log` writes a tool result once, as `Content`.** The second copy,
  `Result (N chars)`, is gone. For a message with images, each text part is
  now written in full under the parts summary. A script that parses the log
  for `Result (` needs to read `Content (` instead.

## CLI and sub-agents

- **A sub-agent's tools display like the parent's**, with its label in front:
  `[generalist 2/15] → read a.py`, with the `replace` diff and shell output.
- **Tool lines show arguments, labels and diffs as typed.** Text in brackets,
  such as `ls [x]` or `x[i]`, was read as Rich markup and dropped, and a stray
  `[/b]` could drop the whole line. Terminal control bytes are removed too.
- **Sub-agent lines show the agent's name again** (`▶ [name]: task`).
- **A foreground sub-agent that raises reports that it ended**, so the CLI and
  the ACP `[sub-agent finished: …]` marker see `AGENT_END` with state
  `cancelled` or `failed`.
- **`agentao --version`** prints `agentao <version>`, also on a library-only
  install.
- **The CLI ends when its input cannot be read** instead of printing `Error:`
  in a loop (`agentao </dev/null`). Ctrl-D on an empty line ends the session.
- **`import agentao.agent` is about 40% faster**: 174 ms → 100 ms (median of 7
  runs, same machine). The shell command floor now compiles its regexes on the
  first shell command.

## Config files

- **An integer literal over 4300 digits is malformed JSON everywhere.** It
  crashed startup, `/replay`, `agentao doctor` and argument parsing, and an ACP
  line holding one got no reply. Each path now handles it like any other
  malformed JSON.
- **No config read can block on a named pipe**, and a path that is not a
  regular file is reported, not read as missing.
- **`"replay.max_instances": true` no longer deletes all but one replay**, and
  an overflowing value no longer crashes startup or `agentao doctor`.
- **`agentao run`, ACP and embedding hosts warn about a `settings.json` whose
  top level is not an object**, as the interactive CLI already did.
- **A bad `mcpServers` file reference in a plugin** no longer drops the whole
  plugin.

## Memory

- **Recall sees memories saved by another session or process** on the same
  `memory.db`.
- **A stable memory that does not fit `<memory-stable>` can be recalled
  again.** With many long stable memories, the ones over the 2,000-character
  budget reached the model through neither block.
- **The warning for a user memory store that cannot be opened** now says what
  happens: user memories are not read, and user-scope writes go to the
  project store.

## Tools

- **macOS sandbox:** a network call blocked by a profile that blocks the
  network (`Could not resolve host`, `getaddrinfo ENOTFOUND`,
  `nodename nor servname provided`) now gets the `[Sandbox hint]`.
- `glob` and the Python fallback of `search_file_content` keep a recursive
  directory prefix (`src/**/test.py` stays in `src`).
- Regex search in git repositories uses `git grep -P`, so `\d`, `\w` and `\b`
  work as in the other backends.
- Editing a file with a name near the filesystem limit no longer fails with
  `ENAMETOOLONG`.
- A skill installed from a repository subdirectory records its own version.

## Documentation

The user guides in `docs/guides/` were folded into the developer guide at
[agentao.cn](https://agentao.cn), in English and Chinese, and checked against
the code. `/goal` has its own CLI chapter. The old files keep their headings
and link to the new sections.

## For hosts

New public names, each from a fix above: `agentao.json_parse.loads()` /
`load()`, `agentao.replay.ReplaySettingsError`,
`agentao.mcp.config.McpConfigWriteError`,
`agentao.replay.config.check_max_instances()`,
`MemoryPromptRenderer.fit_stable_records()`, `SandboxProfile.denies_network`
and `agentao.sandbox.policy.profile_denies_network()`.

## Upgrading

```bash
pip install -U agentao
```

Check the five [behaviour changes](#behaviour-changes) above. See
`CHANGELOG.md` for the full list.
