# Agentao 0.5.19

This release is about messages with images and other non-text parts. Before,
a message part that a wire protocol could not send raised an error, and every
later turn in the session raised it again, so the session could not go on.
Now such a part is sent as a short text note and the turn goes ahead. The
release also raises the default context window to 256K tokens.
One change behaves differently on upgrade; see
[Behaviour changes](#behaviour-changes).

## Behaviour changes

- **The default context window is 256K tokens, up from 200K** (#620). The
  default applies to `Agentao(max_context_tokens=)`, `ContextManager`, the
  CLI's `AGENTAO_CONTEXT_TOKENS` and sub-agents whose parent sets no value.
  With 200K, compaction started early on current models, whose windows are
  256K to 1M tokens. The value is 256,000, not 262,144, so it fits in a
  262,144-token window. A model with a smaller real window is still narrowed
  by `effective_max_tokens`: by a limit named in an overflow error, or by the
  Models API on `anthropic-messages`. To keep the old budget, set
  `AGENTAO_CONTEXT_TOKENS=200000` or pass `max_context_tokens=200_000`.

## Fixes

- **A part a wire cannot express no longer blocks the session** (#615). On
  `anthropic-messages` and `openai-responses`, these parts now go out as a
  text note, with a warning in `agentao.log`:
  - an unknown part type, for example `input_audio` from
    `openai-completions` after a provider switch;
  - a part that is not an object, or a `content` that is neither text nor a
    list;
  - a `text` part whose `text` is not a string;
  - on `anthropic-messages`, an image in the system prompt or in an
    assistant turn.

  Before, an unknown part type raised on both wires, on that turn and every
  later one. Other cases raised too, or were dropped silently. History is
  unchanged, so switching back to a wire that can send the part sends it
  again.
- **A bare-string `image_url` no longer blocks the session** (#613, #616).
  On `anthropic-messages` and `openai-responses`, a string `image_url` is
  taken as the URL. Before, it raised on that turn and every later one. On
  `openai-completions`, the string is now sent as `{"url": ...}`, the shape
  the schema takes. Gemini's OpenAI-compatible endpoint answered the string
  with a 400 (`Value is not a struct`), so every later turn failed there too.
  History is unchanged on every wire.
- **Responses image detail is preserved** (#607). Explicit
  `image_url.detail` values of `low`, `high`, `auto` and `original` now
  reach the `openai-responses` request. Before, they were dropped during
  translation. Other values are still dropped, now with a warning in
  `agentao.log`.
