# Agentao 0.5.9

A small release that makes the ACP Registry listing possible.

**`agentao --acp` and `agentao --login` now run from a bare install**, without
the `[cli]` extras:

```bash
uvx agentao@0.5.9 --acp      # what an ACP Registry client launches
uvx agentao@0.5.9 --login    # configure the LLM provider in a terminal
```

0.5.8 documented `uvx 'agentao[cli]@0.5.8' --acp`. That form still works, but
the Registry cannot use it: its tooling looks the package up on PyPI by the
name before the version separator, which for `agentao[cli]@0.5.8` is
`agentao[cli]`, and PyPI answers 404. Until 0.5.9, the bare `agentao` stopped
at "agentao CLI requires extra packages (missing: rich)". Both modes are now
handled before that check. Every other command still needs `[cli]`, and the
interactive CLI is unchanged.

Without `rich`, the login uses plain terminal prompts. The API key is still
hidden when typed at a terminal; when stdin is piped, the answer is read from
stdin. With `rich` installed the login looks as before. The login command an
`auth_required` error suggests is now `uvx agentao@<version> --login`.

## Fixed

- **`agentao init` and `agentao --login` no longer crash** when you choose a
  CUSTOM provider and press Enter at the base URL or model prompt. The
  question is now asked again instead of ending in an `AttributeError`.

## Upgrading

```bash
pip install -U agentao
```

No configuration changes are needed.
