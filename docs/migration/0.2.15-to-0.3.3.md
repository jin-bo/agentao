# Migrating from 0.2.15 to 0.3.3

**Status:** historical upgrade note for the embedded-harness releases (0.2.16, 0.3.0, 0.3.1, 0.3.3). Later breaks have their own notes: [0.3.x → 0.4.0](0.3.x-to-0.4.0.md), [0.4.x → 0.5.0](0.4.x-to-0.5.0.md).
**Changelog:** [`CHANGELOG.md`](../../CHANGELOG.md), sections `[0.2.16]` to `[0.3.3]`.

---

## TL;DR

The embedded-harness work shipped over four releases. Code that worked on 0.2.15 lands on 0.3.3 with two mechanical changes:

1. Pass `working_directory=` to `Agentao(...)`, or build the agent with `build_from_environment()`.
2. If you build a `MemoryManager` yourself, pass it pre-built stores instead of root paths.

Each step from 0.3.0 to 0.3.3 needs no host code change.

| Release | Kind | What a host does |
|---|---|---|
| 0.2.16 | Soft deprecation | Nothing breaks. `Agentao()` without `working_directory=` warns |
| 0.3.0 | **Breaking** | Add `working_directory=`. Migrate direct `MemoryManager(...)` calls |
| 0.3.1 | Added only | Optional: adopt `events()` and `active_permissions()` |
| 0.3.3 | Added only | Nothing. The package ships a `py.typed` marker |

---

## From 0.2.15

On 0.2.15, `Agentao()` read the environment, the process cwd and `.agentao/` files by itself:

```python
agent = Agentao()   # 0.2.15: implicit env / cwd / .agentao reads
```

0.2.16 warns on this call with a `DeprecationWarning`. 0.3.0 raises `TypeError`. Replace it with one of:

```python
from pathlib import Path
from agentao import Agentao
from agentao.embedding import build_from_environment
from agentao.llm import LLMClient

# Option A: the factory. Matches the old behaviour.
agent = build_from_environment(working_directory=Path.cwd())

# Option B: pure injection. Deterministic, preferred for embedded hosts.
agent = Agentao(
    working_directory=Path("/srv/myapp/run-1"),
    llm_client=LLMClient(api_key=..., base_url=..., model=...),
)
```

Resolve the path before you pass it, so the frozen value is absolute. The factory falls back to `Path.cwd()` when you omit it. That is fine for a CLI entry point and wrong for a server that runs several sessions.

## From 0.2.16

0.2.16 warned and did not break. On 0.3.0 the same call raises `TypeError` from Python's signature check. Add `working_directory=` and you are done.

To find the remaining call sites before you upgrade, run your tests with warnings as errors:

```bash
pytest -W error::DeprecationWarning tests/
```

Tests that called `Agentao()` without the argument on purpose pass `working_directory=tmp_path`, or assert the break with `pytest.raises(TypeError)`.

## Other 0.3.0 breaking changes

- **`MemoryManager(project_root=, global_root=)` is gone.** Pass pre-built stores:

  ```python
  from agentao.memory import MemoryManager, SQLiteMemoryStore

  mgr = MemoryManager(
      project_store=SQLiteMemoryStore.open_or_memory(project_dir / "memory.db"),
      user_store=SQLiteMemoryStore.open(user_dir / "memory.db"),
  )
  ```

  The factory builds the stores itself, so only direct callers change.
- **`MemoryManager._project_root` and `._global_root` are gone.** Read `manager.project_store.db_path` instead. A host-supplied store may expose no path at all.
- **`MemoryStore` moved.** Import it from `agentao.capabilities`, not `agentao.memory`. Today the stable path is `agentao.host.protocols`.
- **No `Path.cwd()` fallback.** `Agentao()` no longer falls back to the process cwd, and the deprecation warning went with the fallback.

## From 0.3.0

0.3.1 adds the host contract and changes nothing you already call. It also adds a direct dependency: **`pydantic>=2`**. If your environment pins Pydantic v1, lift the pin before you upgrade.

What you can adopt:

- `agent.events(session_id=None)`: an async iterator over `HostEvent` (`ToolLifecycleEvent`, `SubagentLifecycleEvent`, `PermissionDecisionEvent`).
- `agent.active_permissions()`: a JSON-safe `ActivePermissions` snapshot (`mode`, `rules`, `loaded_sources`).
- The public contract package, with the event models, `EventStream`, `RFC3339UTCString` and the schema export helpers.

In 0.3.1 that package was `agentao.harness`. It became `agentao.host` in 0.4.2, and the old path was removed in 0.5.0. Write new code against `agentao.host`. The current reference is [developer guide 4.7](../../developer-guide/en/part-4/7-host-contract.md).

What stays internal, so do not depend on it:

- `agentao.transport.AgentEvent` and `Transport.emit(...)`: richer, but they can change in any release.
- `agentao.runtime.identity.*`: id helpers, private to the runtime.
- `agentao.host.projection.*`: the internal redaction layer.

## From 0.3.1

0.3.3 is additive only. It ships the PEP 561 `py.typed` marker, so `mypy` and `pyright` now read Agentao's type hints. A strict type checker can report new findings in your code after the upgrade. No host code change is required.
