# Migrating from 0.4.x to 0.5.0

**Status:** active migration guide for the 0.5.0 release.
**Inventory this was built from:** `docs/design/0-5-0-removal-checklist.md`.

0.5.0 is a **removal release**. It adds nothing you have to adopt — its one
addition, the `anthropic-messages` wire protocol, is opt-in (see *What did not
change*). Everything
in §1–§3 warned with a `DeprecationWarning` through 0.4.x — `agentao.harness`
since 0.4.2, the rest since 0.4.5. **§4 and §5 never warned**, because there
was nothing deprecated about the call: read those two even if your 0.4.x run
is warning-free.

---

## TL;DR — am I affected?

Run your own test suite on the last 0.4.x with warnings as errors:

```bash
python -m pytest -W error::DeprecationWarning
```

Clean means §1, §2 and §3 do not touch you. Then grep for the two that cannot
show up that way:

```bash
grep -rnE "(save_session|load_session|load_session_record|persist_agent_session|list_sessions|delete_session|delete_all_sessions)\(" your_package/
grep -rnE "Agentao\(" your_package/     # any call with more than five positional arguments
```

| § | What | Symptom on 0.5.0 | Warned in 0.4.x? |
|---|---|---|---|
| 1 | `agentao.harness` | `ModuleNotFoundError` | yes, since 0.4.2 |
| 2 | `agentao.session` | `ModuleNotFoundError` | yes, since 0.4.5 |
| 3 | The eight `Agentao(...)` callback kwargs | `TypeError: unexpected keyword argument` | yes, since 0.4.5 |
| 4 | `project_root` on `agentao.embedding.sessions` | `TypeError` naming `project_root` | **no** |
| 5 | Positional arguments to `Agentao(...)` past the fifth | `TypeError: takes … positional arguments` | **no** |
| 6 | Private attributes on `Agentao` | `AttributeError` | no (private) |
| 7 | The "Reasoning Requirement" prompt section | none — the prompt is shorter | no |

## 1. `agentao.harness` → `agentao.host`

The alias package is deleted. The rename is mechanical — `harness` → `host`,
`Harness` → `Host` — in the module path and in every symbol:

| 0.4.x | 0.5.0 |
|---|---|
| `agentao.harness` (and `.events` / `.models` / `.projection` / `.protocols` / `.replay_projection` / `.schema`) | `agentao.host` (same submodules) |
| `HarnessEvent` | `HostEvent` |
| `HarnessToolEmitter` / `HarnessPermissionEmitter` / `HarnessSubagentEmitter` | `HostToolEmitter` / `HostPermissionEmitter` / `HostSubagentEmitter` |
| `HarnessReplaySink` | `HostReplaySink` |
| `harness_event_to_replay_kind` / `harness_event_to_replay_payload` | `host_event_to_replay_kind` / `host_event_to_replay_payload` |
| `replay_payload_to_harness_event` | `replay_payload_to_host_event` |
| `export_harness_event_json_schema` / `export_harness_acp_json_schema` | `export_host_event_json_schema` / `export_host_acp_json_schema` |

Every other name was already spelled the same under both paths. The objects
are the same objects, so nothing about event payloads, schemas or snapshots
changes.

If you upgrade a source checkout in place, delete the leftover
`agentao/harness/__pycache__` directory: Python imports a directory with no
`__init__.py` as an empty namespace package, so `import agentao.harness` can
appear to succeed while every `from agentao.harness import …` fails. A `pip`
install is not affected.

## 2. `agentao.session` → `agentao.embedding.sessions`

```python
# 0.4.x
from agentao.session import save_session, load_session

# 0.5.0
from agentao.embedding.sessions import save_session, load_session
```

The shim did one thing besides re-export: it supplied `Path.cwd()` when you
passed no `project_root`. That fallback is gone everywhere — see §4, which
applies to you as well.

## 3. The eight callback kwargs on `Agentao(...)`

`confirmation_callback`, `step_callback`, `thinking_callback`,
`ask_user_callback`, `output_callback`, `tool_complete_callback`,
`llm_text_callback` and `on_max_iterations_callback` are no longer parameters.
The attributes of the same names on the agent (`agent.confirmation_callback`,
…) are gone with them. Two ways forward, and the first is a one-line change.

**Keep your callbacks; wrap them.** `build_compat_transport` takes the same
eight names and is not deprecated — it is the supported migration surface:

```python
from agentao import Agentao
from agentao.embedding.compat import build_compat_transport

agent = Agentao(
    working_directory=project_dir,
    transport=build_compat_transport(
        confirmation_callback=my_confirm,
        llm_text_callback=my_print,
        step_callback=my_step,
    ),
)
```

**Or move to the event stream.** One `on_event` handler replaces the five
display callbacks; the three interactive ones have their own keyword:

| Callback | `SdkTransport(...)` |
|---|---|
| `confirmation_callback` | `confirm_tool=` |
| `ask_user_callback` | `ask_user=` |
| `on_max_iterations_callback` | `on_max_iterations=` |
| `step_callback` | `on_event=` — `TURN_START`, `TOOL_START` |
| `thinking_callback` | `on_event=` — `THINKING` |
| `output_callback` | `on_event=` — `TOOL_OUTPUT` |
| `tool_complete_callback` | `on_event=` — `TOOL_COMPLETE` |
| `llm_text_callback` | `on_event=` — `LLM_TEXT` |

See `developer-guide/en/part-4/3-sdk-transport.md`.

With no `transport=` at all the agent still gets a `NullTransport`: silent,
and it approves every confirmation. That default is unchanged.

`ToolRunner(...)` also stopped accepting the four callback kwargs it had been
ignoring since the Transport protocol landed. It is an internal runtime class;
this only matters if you construct one yourself.

## 4. `project_root` is required on `agentao.embedding.sessions` — **never warned**

In 0.4.x all seven entry points took `project_root: Optional[Path] = None`,
and `None` meant the process's current directory. That held for a direct
caller of `agentao.embedding.sessions` too, not only for the `agentao.session`
shim — and nothing warned, because nothing about the call was deprecated.

In 0.5.0 it is required, and **an explicit `project_root=None` is refused as
well** (`TypeError`), rather than quietly resolving to the cwd. The point is
`delete_all_sessions` as much as `save_session`: a host whose own root
variable was unset used to read, write and delete some other project's
sessions without a word.

| Function | 0.5.0 signature |
|---|---|
| `save_session(messages, model, active_skills=None, session_id=None, *, project_root)` | keyword-only |
| `persist_agent_session(agent, session_id=None, *, project_root)` | keyword-only |
| `load_session(session_id=None, *, project_root)` | keyword-only |
| `load_session_record(session_id=None, *, project_root)` | keyword-only |
| `list_sessions(project_root)` | required |
| `delete_session(session_id, project_root)` | required |
| `delete_all_sessions(project_root)` | required |

**Pass `project_root=` by keyword and every one of them works.** It is
keyword-only on the first four because it follows optional parameters there; a
call that passed it positionally (`load_session(sid, root)`) now raises.

If the cwd really is what you mean, say so: `project_root=Path.cwd()`.

## 5. `Agentao(...)` takes five positional arguments — **never warned**

The eight callbacks sat *between* other parameters, positionally:

```
api_key, base_url, model, temperature, max_tokens,
confirmation_callback, max_context_tokens, step_callback, …,
permission_engine, on_max_iterations_callback, transport, plan_session
```

Deleting them would have moved `max_context_tokens`, `permission_engine`,
`transport` and `plan_session` up, and a call still passing a callback sixth
would have bound it to `max_context_tokens` silently. So everything after
`max_tokens` is keyword-only now, and that call is a `TypeError` where it is
written. If you pass those four by keyword — as every example in the docs
does — nothing changes for you.

## 6. Private attributes removed from `Agentao`

Underscore-prefixed, never part of the contract, listed because some test
suites reached for them:

| Removed | Use instead |
|---|---|
| `agent._replay_config` | `agent.replay_manager.config` |
| `agent._replay_recorder` | `agent.replay_manager.recorder` |
| `agent._replay_adapter` | `agent.replay_manager.adapter` |
| `agent._host_replay_sink` | `agent.replay_manager.host_replay_sink` |
| `agent._emit_context_compressed(...)` | `agentao.replay.observability.emit_context_compressed(agent, ...)` |
| `agent._emit_session_summary_if_new(prev)` | `agentao.replay.observability.emit_session_summary_if_new(agent, prev)` |
| `agent._latest_session_summary_id()` | `agentao.replay.observability.latest_session_summary_id(agent)` |

`agent.replay_manager` is `None` on an agent that never had replay attached
(a bare `Agentao(...)` with no `replay_config=`). The old `_replay_config`
returned a disabled default there; check for `None` yourself.

A test that *patched* `agent._emit_context_compressed` to capture the event
should capture it from the transport instead — the payload keys on the wire
are `type`, `reason`, `pre_msgs`, `post_msgs`, `pre_est_tokens`,
`post_est_tokens`, `duration_ms`.

**Not removed**, although the 0.4.5 release notes listed them for 0.5.0:
`agent.start_replay()`, `agent.end_replay()`, `agent.reload_replay_config()`
and the `replay_config=` constructor argument. The CLI and the ACP server call
them on every session; they stay.

## 7. The "Reasoning Requirement" prompt section is retired

Until 0.5.0 the system prompt gained a `=== Reasoning Requirement ===` section
when — and only when — `thinking_callback=` was passed to the constructor.
Nothing else set that flag: a host on `transport=` never had the section,
including one that had wrapped a `thinking_callback` with
`build_compat_transport` as recommended, and including agentao's own CLI, ACP
server and `agentao run`, since 2026-04-04. The kwarg is gone and the section
went with it, rather than being switched on for every host that never had it.

If you passed `thinking_callback=` and want the instruction back, put it in
your project's `AGENTAO.md`, which is the first section of the system prompt:

```
=== Reasoning Requirement ===
Before any tool call that modifies state, runs a shell command, or is part of a multi-step investigation, write 2-3 sentences:
- Action: What tool you are calling and with what input.
- Expectation: What you expect to find or what the result should confirm.
- If wrong: What you will do if the result contradicts your expectation.
Skip this preamble for trivial read-only lookups (single read_file, list_directory, glob). Be specific and falsifiable when you do write it.
```

`THINKING` events are unaffected — they carry the model's reasoning output and
never depended on this section.

## What did not change

- `agentao.embedding.compat.build_compat_transport` — kept, on purpose.
- `agentao.tool_runner` (the old import path of `agentao.runtime.tool_runner`)
  — a different shim, not part of this release.
- Event payloads, the ACP schema snapshots, configuration files, the CLI.
- The wire protocol. 0.5.0 can speak Anthropic's Messages API natively
  (`{PROVIDER}_API_FORMAT=anthropic-messages`, `api_format=`), but only when
  told to: nothing is inferred from a URL, a provider name or a model name, and
  an existing deployment stays on Chat Completions. The one thing every install
  does see is a **new core dependency**, `anthropic>=1.6.0` (with
  `docstring-parser`); it is imported lazily and never loaded on the default
  wire. See `docs/reference/configuration.md` §2.
